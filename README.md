# MathTasks

Сайт-решебник по школьной математике: задачи с разбором решений, разложенные по классам 1–12 (в соответствии со стандартами Skola2030).

Структура каталога — четыре уровня: **раздел** (Алгебра, Геометрия, …) → **тема** → **подтема** (опционально) → **задача**. Класс при этом работает как глобальный контекст: посетитель выбирает свою параллель один раз, и меню, главная и поиск показывают только её.

## Стек

- **Клиент**: Статические страницы и нативный модульный JavaScript без обязательной сборки приложения в рантайме — Vite используется для локального сервера разработки и сборки в `dist/`.
- **Сервер / Edge**: Cloudflare Workers (`worker/index.js`) раздаёт статику (`wrangler.jsonc`), генерирует динамический `/sitemap.xml`, формирует Open Graph мета-теги для ботов соцсетей и мессенджеров на `/task/*`, а также проксирует запросы к Gemini API (`/api/generate-task`).
- **База данных и аутентификация**: Supabase (PostgreSQL + Row Level Security).
- **Хранилище чертежей**: Supabase Storage (бакет `task-images`). Исходные чертежи условий хранятся в репозитории (`task-svgs/condition/`) и синхронизируются через `npm run sync:svgs`.
- **Формулы**: KaTeX для инлайн- и выключных математических выражений.
- **Интернационализация**: Двуязычный интерфейс и каталог (русский и латышский языки).

| Файл / Каталог | Назначение |

## Установка

```bash
npm install
cp public/config.example.js public/config.js   # вписать URL и publishable-ключ проекта
npm run dev
```

`config.js` находится в `.gitignore`: публичный ключ привязан к конкретному проекту, поэтому у каждого окружения он свой. При сборке в CI/CD скрипт `scripts/prepare-config.js` может автоматически генерировать `public/config.js` из переменных окружения `SUPABASE_URL` и `SUPABASE_KEY` (или `SUPABASE_ANON_KEY`).

| `supabase/migrations/017_planimetrija_icon.sql` | Значок раздела «Планиметрия» (замена глифа на эмодзи 🔺) |

| `supabase/migrations/021_optional_task_title.sql` | Необязательный заголовок задачи (`tasks.title` со значением по умолчанию `''`) |

Базовый язык — русский, он лежит в основных колонках; латышский — в парных с суффиксом `_lv`. Английского на сайте нет.

`schema.sql` отстаёт от миграций: в нём нет бакета для чертежей, латышских колонок, кросс-тегов, подсказок, подтем и сообщений об ошибках, а `id` объявлены как `GENERATED ALWAYS`. Поэтому одного `schema.sql` для чистого проекта мало — после него нужно выполнить миграции по порядку. Актуальная схема сейчас — это `schema.sql` плюс все миграции.

### Администратор

Роль хранится только в `public.profiles`; в `auth.users` колонки роли нет и не должно быть — приложение читает `profiles`.

1. Зарегистрируйте пользователя (Supabase → Authentication → Add user).
2. Выполните третий запрос из `supabase/check_admin.sql`, подставив свою почту.

Первый и второй запросы того же файла показывают связку пользователь ↔ профиль: если админка отказывает, начинать нужно с них. Частая причина — строку в `profiles` завели руками со случайным UUID, и к аккаунту она не относится.

## Формулы

Условие, подсказка и решение — **обычный текст**, формулы внутри него берутся в разделители:

```
Решите уравнение $2x^2 - 5x - 3 = 0$
По формуле Герона $$S=\sqrt{p(p-a)(p-b)(p-c)}$$
```

`$…$` — формула в строке, `$$…$$` — отдельной строкой по центру. Работают также `\(…\)` и `\[…\]`.

Так пробелы в словах остаются на месте, а `%` не превращается в начало LaTeX-комментария, съедающий остаток условия. В админке под каждым полем есть живой предпросмотр — он показывает ровно то, что увидит посетитель.

## Разработка

```bash
npm run dev              # дев-сервер на Vite (порт 5173)
npm test                 # запуск всех тестов в Vitest
npm run verify           # комплексная верификация базы и каталога
npm run build            # сборка в dist/
npm run sync:svgs        # загрузка SVG-чертежей из task-svgs/condition в Supabase Storage

```

### Тесты

Тесты запускаются через Vitest (`npm test`) и охватывают 8 файлов в папке `tests/`:

1. `tests/lib.test.js` — чистые функции из `public/lib.js`: транслитерация слагов, разделители KaTeX, очистка поисковых запросов от спецсимволов PostgREST, парсинг и сравнение математических ответов.
2. `tests/trainer.test.js` — движок устного счёта `public/trainer.js`: генерация примеров, валидация ответов, поддержка дробей, степеней и отрицательных чисел, форматирование времени.
3. `tests/worker.test.js` — серверный воркер `worker/index.js`: транслитерация слагов, санитизация формул LaTeX для превью, распознавание ботов, формирование путей и XML для sitemap, генерация Open Graph разметки и маршрутизация.
4. `tests/ai-generator.test.js` — AI-генератор задач: структура промптов для Gemini, валидация полей Skola2030, очистка и разбор JSON-ответов с LaTeX.
5. `tests/verify-answers.test.js` — математический анализатор ответов: трансляция LaTeX в JS, интервалы, корни, уравнения, принадлежность множествам.
6. `tests/admin-refs.test.js` — валидация связей идентификаторов элементов между `admin.html` и `admin.js`.
7. `tests/admin-shell.test.js` — проверка структуры разметки, вкладок и контейнеров панели администратора.
8. `tests/no-secrets.test.js` — статический аудит клиентских скриптов на отсутствие случайно оставленных секретов и приватных API-ключей.

### Верификация данных и каталога

- `npm run verify` — запускает комплекс проверок:
  - `verify:answers` — валидация и сверка математических ответов задач;
  - `verify:consistency` — проверка целостности структуры каталога (привязки тем, подтем, классов);
  - `verify:pairing` — проверка языкового паритета между RU и LV (наличие переводов условий, подсказок, решений);
  - `verify:parity` — сверка математических формул между русскими и латышскими версиями.

## Выкладка

Сайт работает на **Cloudflare Workers** со статической раздачей ассетов (Workers Static Assets):

1. `npm run build` выполняет:
   - `scripts/prepare-config.js` — генерирует `public/config.js` из переменных окружения `SUPABASE_URL` и `SUPABASE_KEY` (если файл не создан вручную);
   - `vite build` — собирает и оптимизирует статику в директорию `dist/`;
   - `scripts/post-build.js` — создаёт `dist/200.html` для SPA-фолбэка и удаляет устаревшие файлы перенаправлений.

2. Маршрутизация статики:
   - Вся маршрутизация описана в `wrangler.jsonc`. Опция `"not_found_handling": "single-page-application"` указывает Cloudflare Workers отдавать `index.html` на клиентские навигационные запросы (прямой заход на `/topic/<slug>`, обновление по F5). Настоящие файлы (`/admin.html`, `/exams.html`, `/formulas/*.pdf`, `/assets/*`) отдаются напрямую.
   - Заголовки безопасности и правила кеширования заданы в `public/_headers` (CSP, `X-Frame-Options`, долгосрочный `Cache-Control` для ассетов).

3. Серверный код (`worker/index.js`):
   Воркер перехватывает запросы до статики (`run_worker_first: ["/sitemap.xml", "/api/*", "/task/*"]`):
   - `/sitemap.xml` — генерирует динамическую карту сайта напрямую из базы Supabase (разделы, темы, подтемы, опубликованные задачи, теги, контрольные работы). Карта не требует ручного обновления при добавлении контента.
   - `/task/<id>-<slug>` — для поисковых и социальных ботов (Telegram, WhatsApp, Discord, VK, Twitter/X, LinkedIn, Slack, Applebot) генерирует HTML-страницу с метатегами Open Graph и Twitter Card (название задачи, очищенное от LaTeX условие, тема и изображение), обеспечивая превью ссылок в чатах. Обычным пользователям отдаётся клиентское SPA-приложение.
   - `/api/generate-task` — прокси к Gemini API (`gemini-3.6-flash`, `gemini-flash-latest`, `gemini-3.5-flash-lite`): ключ хранится в секретах воркера, а не в браузере. **Проверки роли пока нет** — если задан `GEMINI_API_KEY`, эндпоинт может вызвать любой, кто знает адрес (см. `docs/ROADMAP.md`, п. 5.4).

4. Переменные окружения и секреты воркера:
   ```bash
   npx wrangler secret put SUPABASE_URL
   npx wrangler secret put SUPABASE_KEY
   npx wrangler secret put GEMINI_API_KEY   # не задавать, пока в /api/generate-task нет проверки роли
   ```

Деплой выполняется командой:
```bash
npx wrangler deploy
```

Внешние библиотеки подключены с фиксированными версиями и `integrity`: при обновлении версии хеш нужно пересчитать, иначе браузер заблокирует скрипт.
