# MathTasks

Сайт-решебник по школьной математике: задачи с разбором решений, разложенные по классам 1–11.

Структура каталога — три уровня: **раздел** (Алгебра, Геометрия, …) → **тема** → **задача**. Класс при этом работает как глобальный контекст: посетитель выбирает свою параллель один раз, и меню, главная и поиск показывают только её.

## Стек

Статические страницы и обычные скрипты без сборки для кода приложения — Vite нужен только для дев-сервера и выкладки. Данные и аутентификация — Supabase (PostgreSQL + RLS). Формулы — KaTeX.

| Файл | Назначение |
|---|---|
| `index.html` | Публичная часть |
| `admin.html` | Админ-панель (отдельная страница, `noindex`) |
| `public/lib.js` | Чистые функции без DOM, покрыты тестами |
| `public/client.js` | Клиент Supabase, тема, рендер формул |
| `public/app.js` | Каталог, маршруты, поиск |
| `public/admin.js` | Управление разделами, темами и задачами |
| `public/config.js` | Ключи Supabase — **не в репозитории** |

## Установка

```bash
npm install
cp public/config.example.js public/config.js   # вписать URL и publishable-ключ проекта
npm run dev
```

`config.js` в `.gitignore`: ключ публикуемый, но привязан к конкретному проекту, поэтому у каждой среды он свой.

## База данных

Запускать по очереди в Supabase → SQL Editor. Порядок важен: миграции опираются на предыдущие.

| Файл | Что делает |
|---|---|
| `supabase/schema.sql` | Установка с нуля: таблицы, RLS-политики, триггер профилей |
| `supabase/migrations/001_add_grades.sql` | Классы у тем и задач |
| `supabase/migrations/002_subjects.sql` | Разделы отдельной таблицей вместо текстового поля |
| `supabase/migrations/003_task_position.sql` | Порядок задач внутри темы |

На чистом проекте достаточно `schema.sql` — он уже включает всё, что добавили миграции. Миграции нужны существующей базе.

### Администратор

Роль хранится только в `public.profiles`; в `auth.users` колонки роли нет и не должно быть — приложение читает `profiles`.

1. Зарегистрируйте пользователя (Supabase → Authentication → Add user).
2. Выполните третий запрос из `supabase/check_admin.sql`, подставив свою почту.

Первый и второй запросы того же файла показывают связку пользователь ↔ профиль: если админка отказывает, начинать нужно с них. Частая причина — строку в `profiles` завели руками со случайным UUID, и к аккаунту она не относится.

## Формулы

Условие и решение — **обычный текст**, формулы внутри него берутся в разделители:

```
Решите уравнение $2x^2 - 5x - 3 = 0$
По формуле Герона $$S=\sqrt{p(p-a)(p-b)(p-c)}$$
```

`$…$` — формула в строке, `$$…$$` — отдельной строкой по центру. Работают также `\(…\)` и `\[…\]`.

Так пробелы в словах остаются на месте, а `%` не превращается в начало LaTeX-комментария, съедающий остаток условия. В админке под каждым полем есть живой предпросмотр — он показывает ровно то, что увидит посетитель.

## Разработка

```bash
npm run dev      # дев-сервер на 5173
npm test         # тесты чистых функций
npm run build    # сборка в dist/
```

Тесты покрывают `public/lib.js` — транслитерацию слагов, чистку поискового запроса от символов, которые PostgREST разбирает как синтаксис фильтра, и разделители KaTeX. Последнее ломалось дважды: при правке файлов `'\\['` схлопывалось в `'['`, и тогда любые квадратные скобки в тексте превращались в формулу.

## Выкладка

`npm run build` собирает статику в `dist/`. Файл `public/_redirects` отдаёт все пути на `index.html` — это понадобится после перехода на History API, иначе прямой заход на `/topic/<slug>` вернёт 404. Формат подходит Cloudflare Pages и Netlify; для Vercel то же правило описывается в `vercel.json`.

Внешние библиотеки подключены с фиксированными версиями и `integrity`: при обновлении версии хеш нужно пересчитать, иначе браузер заблокирует скрипт.
