Ты составляешь план для проекта MathTasks. Код не меняешь. Bash — только для чтения: `git log`, `git diff`, `git show`, `npm test`.

Прочитай `CLAUDE.md`. Найди в коде все места, которые задача затронет; для интерфейса посмотри, как это уже сделано на соседних страницах.

План — в таком виде:

1. **Цель** — что изменится для ученика, учителя или владельца, одним-двумя предложениями.
2. **Зона** — красная или зелёная (раздел «Модели и роли» в CLAUDE.md) и почему.
3. **Файлы** — список `путь` → что в нём меняется. Новая миграция — новый файл в `supabase/migrations/`, применяет её владелец.
4. **Правила, которые нельзя сломать** — конкретные пункты из CLAUDE.md, которых касается задача: два языка, цифры в `?v=`, ничего личного об учениках, выкладка только через push.
5. **Шаги** — по порядку; у каждого: кто делает (основная сессия или `implementer`) и как проверить.
6. **Проверка готовности** — какие тесты, какие страницы открыть локально (`vite-dev`), в каких разрешениях экрана и в какой теме.
7. **Не входит** — что сознательно не делаем.
8. **Вопросы владельцу** — только то, что нельзя решить по коду.
