# Пачка новых задач для MathTasks

Один запуск — одна пачка: до 12 задач, из них до 3 с самопроверкой, в одну или две подтемы одной темы. Работаешь сам, без вопросов: по расписанию спросить некого. Если что-то не получается — закрой пачку как неудачную, а не публикуй сомнительное.

**Границы.** Меняется только база задач, и только через скрипты этого скилла. Никаких коммитов, пушей, правок файлов репозитория, новых подтем, картинок. Чужие и старые задачи не трогать. Все команды — инструментом Bash из корня репозитория (`C:\Users\goga8\Downloads\MathTasks`), ровно в том виде, как написано ниже.

## 1. Выбор подтемы

```bash
node .claude/skills/add-tasks/scripts/pick.mjs --grades <классы потока>
```

Запуски идут потоками, по одному на набор классов: 10, 11, 12, 9 и 6,7,8. Классы потока даёт задание расписания («поток: --grades 10») — передай их ровно так. Без `--grades` берутся все классы 6–12 (для ручного запуска); пока идёт хоть один поток, такой запуск отвечает «ЗАНЯТО». У каждого потока свой замок, потоки работают одновременно и не мешают друг другу.

- Код 3 «ЗАНЯТО» — в этом потоке ещё идёт предыдущий запуск. Код 4 «ВСЁ ЗАПОЛНЕНО» — во всех подтемах классов потока уже по 45 задач. В обоих случаях сделай шаг 6 и закончи отчётом в одну-две строки.
- «НЕЗАВЕРШЁННАЯ ПАЧКА» — выполни показанную команду `publish.mjs <пачка>`, перескажи итог и закончи.
- Иначе скрипт создал пачку (`ПАЧКА 20261012-1500`) и напечатал контекст: план по подтемам («Написать задач: N, из них с самопроверкой: K» и по каждой подтеме — сколько обычных и сколько с самопроверкой), тему, программу, соседние подтемы, уже имеющиеся задачи и образцы оформления. Это и есть задание.

## 2. Правила

Прочитай `.claude/skills/add-tasks/rules.md` целиком — каждый раз. Там формат файла, допустимые формы ответа, требования к LV и что есть и чего нет в программе каждого класса.

## 3. Пачка

В своём scratchpad (а если его нет — в `.claude/skills/add-tasks/state/batches/<пачка>/`) создай инструментом **Write**:

- `tasks.mjs` — задачи по плану pick.mjs: у каждой `sub` подтемы из плана, у задач с самопроверкой `self: true` (что это и как писать — rules.md). Разные типы, смесь сложности, ничего не повторяет существующие задачи подтемы.
- `verify.py` — независимый пересчёт ответа каждой задачи; последняя строка вывода — JSON со значениями полей ответа, а для задачи с самопроверкой — `true` как итог вычисленной проверки утверждения (формат в rules.md).

Перед проверкой перечитай каждую задачу как ученик: данных хватает, ответ единственный, решение приходит к ответу, латышский текст — точный перевод русского, задача по программе класса и по этой подтеме.

## 4. Проверка

```bash
node .claude/skills/add-tasks/scripts/check.mjs <пачка> <папка с tasks.mjs и verify.py>
```

Код 0 — чисто. Код 2 — список проблем по задачам: исправь файлы инструментом **Edit** и запусти снова. В Bash — только команды `node .claude/skills/add-tasks/scripts/…` из этого файла: ничего другого ни для правки, ни для проверки или расчёта (`python`, heredoc, `sed`, `node -e`). Такие команды не входят в разрешённые, запуск без людей встаёт на вопросе о разрешении и держит замок потока, а heredoc ещё и съедает обратные слэши. Расхождение пересчёта — повод заново решить задачу, а не подогнать verify.py. Если задачу не удаётся довести за пару попыток — удали её из tasks.mjs (и её значение из verify.py, перенумеровав ключи). Не больше 5 прогонов; если чистой пачки так и не вышло:

```bash
node .claude/skills/add-tasks/scripts/finish.mjs <пачка> --failed "кратко, что не вышло"
```

Если подтема не годится ни для обычных задач, ни для задач с самопроверкой — `finish.mjs <пачка> --skip-sub "причина"` (главная подтема — пачка закрывается) или `--skip-sub "причина" --sub <id>` (вторая подтема плана — отсеивается, пачка продолжается с главной). Недобор по плану (написано меньше, чем просил pick.mjs) — не ошибка: check.mjs пишет его отдельной строкой.

## 5. Вставка и публикация

```bash
node .claude/skills/add-tasks/scripts/check.mjs <пачка> <папка> --insert
node .claude/skills/add-tasks/scripts/publish.mjs <пачка>
```

`--insert` ещё раз проходит все проверки и пишет задачи черновиками. `publish.mjs` перечитывает их из базы, публикует чистые, перенумеровывает тему и проверяет страницы `mathtasks.lv/ru/task/<id>` и `/task/<id>`. После `--insert` tasks.mjs не править: publish.mjs сверяет базу с файлом и расхождение оставит черновиком.

## 6. Проверка автозапуска

```bash
node .claude/skills/add-tasks/scripts/audit.mjs
```

Перепроверяет последние 120 задач, выложенных скиллом (опубликованы, робот и KaTeX чистые, названия не повторяются, страницы на сайте открываются), и сам автозапуск (давно ли была удачная публикация, нет ли неудач подряд, брошенного замка, застрявших черновиков). Код 2 — замечания: ничего не исправляй сам, просто перенеси их в отчёт. Делай этот шаг и тогда, когда pick.mjs сказал «ЗАНЯТО» или «ВСЁ ЗАПОЛНЕНО».

## 7. Итог

Короткий отчёт пользователю (2–4 строки): подтемы (код и название), сколько задач опубликовано и их id, сколько из них с самопроверкой, что осталось черновиком или не получилось и почему, замечания audit.mjs (если есть). Журнал всех запусков: `node .claude/skills/add-tasks/scripts/pick.mjs --status`.

## Справка

- Состояние — `.claude/skills/add-tasks/state/` (не в git): `lock-<поток>.json` (например `lock-10.json`, `lock-6-7-8.json`), `log.jsonl`, `skip.json`, `batches/<пачка>/` (id пачки кончается на поток: `20261121-1330-g10`).
- Настройки: классы `GRADES` и первые классы `PRIORITY_GRADES` — в `scripts/common.mjs`; потолок подтемы `TARGET` = 45, доля самопроверки `SELF_EVERY` = 5 (1 из 5), пачка `PER_RUN` = 12, из них `SELF_PER_RUN` = 3 с самопроверкой, подтем в пачке `MAX_SUBS` = 2 — в `scripts/quota.mjs`.
- Замок держится до конца запуска; брошенный (старше 75 минут) pick.mjs снимает сам. Снять брошенные вручную: `finish.mjs --unlock --grades 10` (один поток) или `finish.mjs --unlock` (все); живой замок — только с `--force`.
- Главная подтема пачки, где два запуска подряд кончились неудачей, больше не выбирается, пока её не уберут из журнала.
