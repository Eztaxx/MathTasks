# Проверки и индексация

## Что проверяется автоматически

**Тесты (`.github/workflows/ci.yml`).** На каждый пуш в `master` и каждый запрос на слияние GitHub
ставит зависимости (`npm ci`) и гоняет `npm test`. Автосборка Cloudflare тесты не запускает,
поэтому красный значок в GitHub — единственный сигнал, что после пуша что-то сломалось.
Настраивать ничего не нужно.

**Задачи в базе (`.github/workflows/audit.yml`).** Раз в сутки (04:17 UTC) и по кнопке
«Run workflow» запускается `node scripts/audit-tasks.mjs --grade 1 --strict`: тот же разбор, что
в админке, по всем опубликованным задачам. Ошибкой считается всё, кроме «самопроверки»:
непринимаемый ответ, разные числа в русском и латышском тексте, лишнее на чертеже, нет подписи
у поля, нет перевода. Нужен, потому что в одну базу пишут несколько сессий и правки идут мимо
репозитория.

Чтобы проверка заработала, в репозитории GitHub добавьте два секрета
(Settings → Secrets and variables → Actions → New repository secret):

| Секрет | Откуда |
| --- | --- |
| `SUPABASE_URL` | адрес проекта Supabase, тот же, что в `public/config.js` |
| `SUPABASE_ANON_KEY` | анонимный ключ (он публичный, лежит в `public/config.js`) |

Пока секретов нет, задание пишет предупреждение и завершается без ошибки. Ключ `service_role`
в GitHub класть не нужно.

Локально то же самое: `npm run audit:tasks -- --grade 1 --strict`.

## Поисковики

Сайт готов к индексации: `robots.txt` указывает на `sitemap.xml`, карту собирает воркер из базы на
каждый запрос (на 30.09.2026 около 5,6 тыс. адресов, 3 МБ; предел — 50 тыс. адресов и 50 МБ),
у страниц есть `canonical`, `hreflang` (lv, ru, x-default) и JSON-LD. Дальше нужен аккаунт Google.

1. Откройте https://search.google.com/search-console и добавьте ресурс `mathtasks.lv`
   (лучше «Домен»: тогда учитываются и `www`, и оба языка).
2. Подтвердите владение. Для ресурса «Домен» — запись TXT в DNS (домен в Cloudflare: DNS → Add record).
   Для «Префикс URL» — мета-тег в `<head>` или файл.
3. Раздел «Файлы Sitemap» → добавьте `sitemap.xml`. Статус должен стать «Успешно».
4. Через неделю-две смотрите «Индексирование → Страницы»: сколько адресов в индексе и почему
   остальные нет. Статус «Обнаружено, но пока не проиндексировано» на новом сайте с тысячами
   страниц — норма: Google открывает их постепенно.
5. Для проверки одной страницы — «Проверка URL» вверху; можно запросить индексацию 10–20 главных
   страниц (классы и темы).
6. По желанию тот же ресурс импортируется в Bing Webmaster Tools одной кнопкой.

## Адреса тем — латышские

Адрес темы — `/topic/skola2030-g<класс>-<номер>-<латышское название>`, номер — позиция темы в классе
(как на сайте: 9.1, 9.2…). Раньше у тем 1–9 классов слаг был транслитерацией русского названия
(`podobnye-treugolniki-1788737251039-299`), 30.09.2026 их заменили (58 тем; у 59 слаг уже был латышским),
а у подтем 9.9.1–9.9.4 исправили устаревший номер `9-11-N` на `9-9-N`.

- Соответствия «старый → новый» лежат в `public/data/slug-redirects.json`. Воркер (`worker/seo.js`,
  `legacyTarget`) отвечает на старый адрес кодом 301 — и для `/topic/`, и для `/control-work/`, и для
  `/subtopic/`, с `/ru/` и без, — но только когда новый слаг уже есть в базе.
- Запасной путь есть и в приложении (`legacyPathOf` в `public/app.js`): оболочка из кеша service worker
  открывается без похода на сервер, адрес в строке заменяется сам.
- Слаг новых разделов, тем и подтем админка собирает от латышского названия.
- Переименовывая слаг темы, добавьте пару в `slug-redirects.json`, иначе старая ссылка умрёт.
- Слаг задачи (`/task/<id>-<слаг>`) зависит от языка страницы: на `/ru/` он из русского названия. Работает
  по id, слаг только для читаемости.
