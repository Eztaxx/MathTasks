# Резервные копии каталога

На бесплатном тарифе Supabase автоматических копий нет. В базе — 435 задач,
полный перевод на латышский, кросс-теги и порядок задач внутри тем. Заново
это не сделать, поэтому копии снимаем сами.

## Снять копию

```bash
npm run backup
```

Выгружает `subjects`, `topics`, `tasks`, `tags`, `task_tags`, `profiles`
в один JSON (около 1 МБ) и удаляет старые, оставляя последние 30.

Полезные ключи:

| Ключ | Зачем |
| :--- | :--- |
| `--dir <папка>` | сложить копию в другое место — например, в синхронизируемую папку |
| `--keep 60` | хранить больше копий |
| `--quiet` | вывести только путь к файлу; удобно для планировщика |

Копия снимается **сервисным ключом**: под публичным ключом политики
доступа прячут черновики, и такая копия молча потеряла бы часть работы.
Если в `.env` нет `SUPABASE_SERVICE_ROLE_KEY`, скрипт об этом предупредит.

Если задачи или темы не выгрузились, файл **не записывается** — иначе
сбой доступа затёр бы предыдущую хорошую копию пустышкой.

## Проверить копию

```bash
npm run backup:check -- docs/backup/snapshots/mathtasks-2026-09-07T20-39-25.json
```

Сверяет число строк с заявленным и смотрит, нет ли задач без условия или
без латышского перевода.

## Восстановить

По умолчанию — вхолостую: показывает, что изменится, и ничего не пишет.

```bash
node scripts/restore.mjs docs/backup/snapshots/<файл>.json
node scripts/restore.mjs docs/backup/snapshots/<файл>.json --apply
node scripts/restore.mjs docs/backup/snapshots/<файл>.json --apply --only tasks
```

Восстановление **дописывает** недостающие строки и приводит существующие
к состоянию из копии. Строки, которых в копии нет, оно **не удаляет**:
иначе возврат одной потерянной темы снёс бы всё, что добавлено после
снятия копии. Лишнее удаляется руками и осознанно.

Копия, снятая с другой базы, отвергается — сверяется имя проекта.

## Куда складывать

Папка `docs/backup/snapshots/` в `.gitignore`: тридцать файлов по мегабайту
в истории репозитория никому не нужны. Но копия, лежащая только на этом
ноутбуке, от потери ноутбука не спасает. Складывайте её туда, что
синхронизируется:

```bash
npm run backup -- --dir "C:/Users/goga8/OneDrive/MathTasks-backup"
```

Раз в месяц имеет смысл положить одну копию в git — тогда она окажется и
на GitHub:

```bash
git add -f docs/backup/snapshots/<файл>.json
git commit -m "Копия каталога за сентябрь"
```

## Как часто

Копия дёшева: около минуты и мегабайт. Разумный порядок — **перед каждым
большим импортом** и раз в неделю просто так. Перед импортом важнее: именно
там теряются данные целыми пачками.

## Ограничение, о котором надо знать

Колонки `id` объявлены как `GENERATED ALWAYS AS IDENTITY`. Пока это так,
**удалённую строку нельзя вернуть под прежним номером** — база запрещает
указывать `id` явно. Задача восстановится под новым номером, и на неё
перестанут указывать кросс-теги, адреса вида `/task/162` и закладки,
сохранённые у посетителей в браузере.

Снимает ограничение миграция `supabase/migrations/019_identity_by_default.sql`:
номера по-прежнему выдаёт база, но указать их явно становится можно.
Выполните её один раз — до того, как копия понадобится всерьёз.

Правка существующих строк работает и без миграции: это проверено на живой
базе — задача была испорчена намеренно и восстановлена из копии.
